## 1. 原型边界

本原型保留原始 8 页信息架构和视觉语言，并补齐正式产品必须出现的状态与分支。新增能力通过页面状态、卡片和局部操作呈现，不新增一级导航。

原型只使用固定深圳场景数据，不连接真实 API，不代表 M1-3 至 M1-8 已经实现。

## 2. 响应式形态

- 移动 H5：390×844 评审画布、顶部页面上下文、单列主内容和底部浮动四项导航；
- 桌面 Web：960×760 评审画布、左侧四项主导航、顶部页面上下文和中央任务内容；
- 移动端与桌面端使用相同的页面、状态名称和产品动作，不建立两套业务语义。

## 4. UI 基线

- 沿用原始纸白、深湾绿、青柠和浅蓝绿配色；
- 产品界面不使用纯黑或近黑描边；深色实心面统一使用深湾绿，设备评审框和容器边界
  分别使用浅灰绿与 `line` Token；
- 沿用宋体展示标题、无衬线正文和等宽状态信息；
- 主体正文和核心控件目标不低于 14px，辅助信息目标不低于 12px；仅装饰眉题和非核心状态码允许 10–11px；
- 主要操作和触控区域目标不低于 44px；
- M02 对话输入框使用独立底部输入坞：移动端位于底部导航上方，桌面端位于内容区
  底部；消息和收藏结果保持独立滚动，并预留遮挡安全区；
- Agent 首页主输入卡采用紧凑布局，附件操作保留不低于 44px 的点击区域；
- Agent 快捷条件采用 32px 视觉高度、10px 圆角，同时保留 44px 触控范围；
- Agent 首页与收藏库使用一致的垂直节奏：同组控件间距 8px、板块间距 16px、
  板块标题到内容 8px；
- 只有计划确认等明确终局动作使用 Sticky CTA；
- 英文只作为装饰眉题，核心状态、来源和操作使用中文。

## 5. 评审方式

1. 使用左侧目录逐页查看 8 个页面；
2. 在右侧“状态演示”切换每页的正常、异常和恢复状态；
3. 使用顶部“移动 H5 / 桌面 Web”检查响应式呈现；
4. 按主流程点击任务入口、识别、消歧、规划、确认、提醒、反馈和分享；
5. 通过“全部页面”比较信息密度，并在右侧保存具体评审意见。
